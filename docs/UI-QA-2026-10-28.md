# UI and recovery QA — October 28, 2026

## Scope and findings

Reviewed landing, sign-up/sign-in, dashboard, setup, preflight, joined call, briefing, report, Answer Lab, history, library and profile. Preserved existing visual identity and interview/provider behavior.

Reproduced and fixed:

- Questions extending outside their tile at 844×390. Added compact height-aware call layouts and safe scroll alignment.
- Mobile camera self-view covering the turn-state prompt. Reserved space and restored mobile progress text.
- Control-bar height changing as Done speaking appeared/disappeared. The control is now consistently placed and disabled when recording is inactive.
- Recording/transcription failure leaving misleading listening state. Errors pause and offer recovery; microphone labels follow actual recording state.
- Unbounded cloud speech request. A 12-second timeout triggers browser speech fallback and allows microphone capture to start. Preparing audio is distinguished from speaking. Browser fallback chooses Hindi/English language tags.
- Briefing keyboard focus escaping the intended controls. Native modal semantics, bounded Tab/Shift+Tab behavior, one-time heading focus and retry/back actions replace the loose overlay.
- Missing joined-call device-disconnection recovery. Track-ended events pause and offer device reconnection. Camera-off also disables the shared video track.
- Protected API 401s producing repeated failed retries. The application returns to sign-in while preserving server-owned interviews.
- Unreadable or failed network responses giving broken or opaque states. Added clear messages and recovery.
- Setup/auth/profile inputs editable during submission. Inputs are locked until completion; setup context remains after failure. Async resume text updates merge with current settings.
- Browser storage restrictions breaking startup. Cleanup of obsolete prototype settings no longer requires localStorage access.
- Answer Lab step indicator not matching the actual next action. Updated current-step semantics and audio preparation text.
- Nested main landmarks in the call. Retained one application main landmark.

## Evidence

- 28 unit/API/provider/geometry tests passed.
- 7 browser flows passed, including expired sessions, invalid credentials, failed setup, unreadable success responses and storage denial.
- 7 media flows passed, including actual fake-device frame/audio capture, Answer Lab retry/transfer, permission denial, missing MediaRecorder, a stalled cloud voice, failed transcription, device reconnection, and briefing generation failure/retry.
- Joined-call geometry checked at 320×480, 320×568, 320×740, 390×844, 768×650, 1024×600 and 844×390. Main product and Answer Lab tests also cover larger widths.
- axe WCAG 2 A/AA checks passed on tested pages and the paused call. Keyboard Tab/Shift+Tab and Escape behavior verified in the briefing.
- TypeScript, ESLint, production build, dependency audit and diff whitespace checks passed. No production dependency vulnerabilities reported by the audit.
- Reviewed production service status and a recent log excerpt: application and Nginx active; inspected requests were successful without application exceptions in that excerpt.

## Limits

Browser automation used Chromium; Safari/Firefox and physical phones were not available. Permission/device-failure scenarios were deliberately simulated; successful media capture used prerecorded browser test devices, not a user's camera/microphone. AI-provider latency and assessment validity remain separate limitations. This is evidence of tested paths, not a guarantee that every device, network or future provider failure is covered.
